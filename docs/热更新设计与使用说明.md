# 简记 · Windows 热更新（自动更新）设计与使用说明

> 版本：v1.0（2026-11-17） ｜ 适用：简记桌面端 0.1.1 及以上
> 机制：Tauri v2 官方 `tauri-plugin-updater`（minisign 签名校验 + NSIS 静默安装 + 自动重启）

## 一、用户视角：如何工作

1. **只需安装一次**：从 Release 页下载 `简记_x.y.z_x64-setup.exe` 安装（0.1.1 及以上版本内置更新器）。
2. **自动检查**：启动约 3 秒后在后台静默检查新版本；发现新版会弹窗询问"立即下载并安装？"，确认后自动下载（toast 显示进度）→ 静默安装 → 自动重启到新版。
3. **手动检查**：设置页 →「检查更新 → 立即检查」。
4. **可调项**（设置页）：
   - 自动检查更新：开/关（持久化到本机数据库 `auto_update_check`）
   - 更新下载源：自动（镜像优先、官方兜底）/ 官方 GitHub / 国内镜像（持久化到 `update_source`）
5. **失败安全**：下载中断、签名校验失败、安装失败 → 新版不会进入安装环节，**旧版完好可继续使用**，重试即可。

## 二、安全模型

| 环节 | 机制 |
|---|---|
| 更新源 | HTTPS 强制；latest.json 先整体校验、再比较版本号 |
| 安装包完整性 | minisign 数字签名：公钥内嵌于应用（`tauri.conf.json → plugins.updater.pubkey`），安装包签名随包发布（`.sig` → latest.json 的 `signature` 字段），验签不过即中止 |
| 版本升级 | 只认更高版本号（SemVer），不会误降级/重装同版本 |
| 用户数据 | SQLite 位于 `%APPDATA%\com.jianji.ledger\`，与程序目录分离，更新/重装均不丢数据 |

**私钥保管**：`%USERPROFILE%\.tauri\jianji.key`（本机）+ GitHub 仓库 Secrets `TAURI_SIGNING_PRIVATE_KEY` / `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`。**私钥或密码丢失将无法再签发可用更新**，只能重新发布需要手动安装的新版本。

## 三、双源托管架构

```
发布：push tag v* → GitHub Actions
  ├─ tauri-action：构建 → 签名 → 创建 Release（exe + .sig + latest.json）
  └─ Sync mirror step：下载产物 → 改写 latest.json 的 url 指向 COS → 上传腾讯 COS

应用内 endpoints（自动源）：
  1. https://<bucket>.cos.ap-guangzhou.myqcloud.com/latest.json   ← 镜像优先（国内直连稳）
  2. https://github.com/YU06118/jianji/releases/latest/download/latest.json ← 兜底
  语义：前一源非 2XX 才尝试下一源；首个成功者生效
```

- latest.json 格式：`{version, notes, pub_date, platforms: {"windows-x86_64": {signature, url}}}`；`signature` 为 minisign 签名**内容**（非路径）；镜像上的 url 必须指向镜像，安装包文件名用 ASCII（`jianji_x.y.z_x64-setup.exe`）。
- **注意**：某源返回 200 但内容非法时**不会**回退到另一源（直接报错），故发布前必须本地校验 latest.json。
- Release 资产名必须精确为 `latest.json`。

## 四、发布 SOP（发新版）

1. 改版本号三处：`desktop/src-tauri/tauri.conf.json`、`desktop/src-tauri/Cargo.toml`、`desktop/package.json` → commit
2. `git tag vX.Y.Z && git push origin main vX.Y.Z`
3. CI 自动完成构建/签名/Release/镜像同步（约 15–25 分钟）
4. 验收：
   - `https://github.com/YU06118/jianji/releases/latest/download/latest.json` 可访问且 windows-x86_64 条目指向 NSIS 包
   - 用已安装的旧版应用触发"立即检查"，走完整更新流程
5. 旧的 `latest.json` 会随每次 Release 覆盖为最新版。

## 五、回滚预案

| 场景 | 处置 |
|---|---|
| 下载/验签/安装失败 | 无需处理：旧版完好，用户重试即可 |
| 新版发布后出现严重 bug | **止血**：删除该 Release 的 `latest.json` 资产（阻止后续用户升级）；注意不能靠把版本号改回旧值来降级——已升级用户不会自动回退 |
| 已升级用户恢复 | 手动下载安装上一版 setup.exe（覆盖安装，数据不丢） |
| 正式修复 | 发布 hotfix：版本号 +1（patch 位），走正常发布 SOP |

**设计取舍**：不实现"自动回滚到上一版"——Tauri 无内置支持，自研成本远超收益；本应用数据层为本地 SQLite 且与程序目录分离，版本兼容风险低，另有 JSON 备份兜底。

## 六、已知限制与说明

- **无二进制差量**：Tauri 每次下载完整安装包（约 3~5 MB，远小于 Electron 类应用的百 MB 级），记账工具低频发版，可接受；如未来需要差量再评估 bsdiff 类方案。
- **杀软/SmartScreen**：未购买 Authenticode 代码签名证书，首次安装可能被 SmartScreen 提示（点"仍要运行"）；minisign 签名保证完整性与来源，但不解决杀软信任问题。发布页附 SHA256 供人工校验。
- **首版种子**：0.1.1 是首个带更新器的版本，需手动安装这一次；之后全部自动。
- **不要用 dev 模式验证安装环节**：`tauri dev` 的安装路径与生产不同；端到端验证一律用构建出的安装包。
- 安装为 passive 模式（小窗+进度条、零交互）；Windows 下安装步骤会自动退出应用（SQLite 写入即落盘，无丢失风险）。

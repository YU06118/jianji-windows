## 1. 项目整体概况

### 1.1 定位与产品设计

- **定位**：开源、本地优先的个人/家庭记账工具。桌面端面向 Windows 日常记账与数据管理，小程序端面向移动场景快速记账。
- **核心约束**：金额全程以「分」整数运算；数据默认只存本机，零网络请求（小程序端为硬约束）；不接入账号体系。
- **需求来源**：`docs/需求文档.md`（30+4 轮调研，v1.0）。注意其中「不做预算」的早期结论与当前小程序已实现预算功能存在冲突，以代码现状为准。

| 维度 | Windows 桌面端 | 微信小程序端 |
|---|---|---|

| 前端文件 | `desktop/frontend/index.html`（内联 CSS + 5 视图）、`app.js`（单 IIFE） | 7 页面 + `app.wxss` 全局设计系统 + `utils/` 5 模块 |

## 5. 关键架构与技术要点

### 5.1 桌面端

1. **无打包器前端**：只有 `index.html` + `app.js`，CSS 内联。不可使用裸模块 `import('@tauri-apps/api/...')`——v0.1.5 实锤这类导入在无打包器环境必抛错，导致更新静默失败。统一用 `window.__TAURI_INTERNALS__.invoke` 与 `window.__TAURI__.*`；`tauri.conf.json` 中 `withGlobalTauri: true`。
2. **WebView2 弹窗陷阱**：原生 `confirm()`/`alert()`/`prompt()` 在 WebView2 下静默失效。所有确认与输入必须自绘：`askConfirm(title, msg, opts)` 返回 Promise，支持 `danger`、`okText`、`input`（替代 prompt）；更新确认另有专用 `confirmUpdate`。
3. **金额分制**：`toCents`/`money` 统一以整数分运算，避免浮点误差。`sanitizeAmt(raw)` 为纯函数：仅留数字与单个小数点、前导零折叠、最多 8 字符，保留 `5.` 尾随小数点形态。
4. **编辑 = upsert 保留 id**：`save_record` 内部 `INSERT ... ON CONFLICT(id) DO UPDATE`。编辑态必须用原 `id`、`ts`、`deleted` 回填，否则会新增重复记录。
5. **动态列表事件委托**：`innerHTML` 重渲染会清掉直接绑定的 onclick。事件绑在不变容器（`#fullList`、`#catGridOut`），用 `e.target.closest()` + `data-id` 定位。
6. **双路径降级**：`IN_TAURI = !!window.__TAURI_INTERNALS__`。非 Tauri 时走 localStorage（`jianji_records`、`jianji_set_*`）并注入 4 条演示数据，隐藏更新入口。新增功能必须同时维护两条路径。
7. **定时器放 Rust，不放 JS**：窗口隐藏时 WebView2 会节流后台定时器。`main.rs` setup 内 `std::thread::spawn` 每 15s 读 settings、比 `chrono::Local::now()` 的 HH:MM、`remind_daily_last_fired` 当日去重，再经 `NotificationExt` 发通知。注意 `use chrono::Timelike`、锁用完 `drop(conn)` 再发通知。
8. **背景渐变层级**：深色 `.window` 用 `--win-bg` = `linear-gradient(180deg,#2E2745,#202020)`；深色 `.main{background:transparent}` **必须放在基础 `.main` 规则之后**，否则同特异性被覆盖，渐变被盖住（v0.1.7 实测踩坑）。
9. **外观手动档**：系统深浅色写在 `@media (prefers-color-scheme: dark)`，手动档用 `html.theme-dark/.theme-light` 全量重声明 token（特异性更高，可压过媒体查询）；`theme_mode` 存 settings，启动时恢复。
10. **本地图片显示**：小票经 `window.__TAURI__.core.convertFileSrc` 转 asset URL。必须在 `tauri.conf.json` 开 `app.security.assetProtocol`（scope `$APPDATA/**`），并在 `Cargo.toml` 给 `tauri` 依赖加 `protocol-asset` feature，否则 `cargo check` 会直接失败。

### 5.2 小程序端

1. **主题双轨制**：`app.wxss` 中 `@media prefers-color-scheme` 只是系统兜底，JS 无法覆盖；手动外观靠根节点 `.mode-dark/.mode-light` 全量重声明 token，复合选择器（如 `.mode-dark.page`）特异性高于页面类，才能压过 `.add-page` 等。
2. **双强调色**：`--pink` 用于前景文字，`--accent-solid` 用于背景（配白字），两者分工避免「紫色背景配紫字」；solid 色全部满足 WCAG AA ≥ 4.5:1。
3. **导航栏单页生效陷阱**：`wx.setNavigationBarColor` 只影响当前页，切 tab 会回退 `theme.json`。方案是 `app.js syncAppearance()` 在页面显示时重设 + `theme.json` 双档统一 `#1E1A2E`。
4. **输入键盘**：`type="digit"` + `sanitizeAmount()` 逐字符重放 `appendAmount` 规则；WXSS 不支持本地路径背景图，但 `<image>` 原生支持本地 SVG。
5. **Canvas 描边裁切**：环形图 stroke 外缘为 `r + lw/2`，半径需反解 `r = (min(w,h)/2 - margin) / (1 + ringRatio/2)`，否则高 DPI 下被裁。
6. **数据校验**：所有写入口经 `safe.js` 白名单重建 + 限额（备注 30 字、备份 2MB、单笔 ≤ 999 万等）；`updateRecord` 不接受外部覆盖 id/ts；`csvCell` 防公式注入。

### 5.3 共享与发版

- `shared/core.js` 提供双端同口径纯函数（`filterRecords`、`summarize`、`trendSeries`、`heatmap`、`toCSV`、`makeBackup`），**目前仅作契约参照与单测，双端运行时各自内置同逻辑**——修改口径时需三处同步。
- **发版链路**（已验证 v0.1.5→v0.1.8）：提交改动 → 三处版本号 bump（`desktop/package.json`、`tauri.conf.json`、`Cargo.toml`；Cargo.lock 由 cargo 自动同步）→ `git tag vX.Y.Z && git push origin vX.Y.Z` → CI 构建签名 → Release 含 exe + sig + latest.json → 客户端「检查更新」。仅改源码不 bump/tag，已安装客户端永远收不到。

### 6.3 工程踩坑

- **编译验证不要 `cargo check | tail` 挂后台**：首次新增依赖时管道缓冲会导致全程无输出、看似卡死 22 分钟（实为下载依赖 + 缓冲）。正确做法：`cargo check > /tmp/xxx.log 2>&1` 重定向到文件，随时 tail 日志；增量编译仅需数秒。判断是否真卡死看 rustc 的 CPU 累计是否增长。
- **Release 全量优化曾挂起**：`Cargo.toml` release 段已降配为 `opt-level=2, lto=false, incremental=true`，勿盲目调回。
- **中文文件名资产**：GitHub 会清洗 Release 中文资产名，CI 中先重命名为 ASCII 再生成 `latest.json`，勿改动该顺序。
- **小程序合规红线**：名称/简介/截图不得出现「理财/投资」；`categories.js` 已将 invest 显示名改为「利息」规避。剪贴板用途必须在 mp 后台声明，否则 `wx.getClipboardData` 调用失败。
- **备份机制脆弱**：小程序备份是复制到剪贴板的文本，需用户自行粘贴保存；卸载小程序或清缓存会丢数据。

## 8. 路线图与暂缓项

> 本章集中记录「明确暂不做 / 待配置 / 待决策」的事项，避免后续接手者误判为遗漏或 bug。
> 原则：先修已有缺陷，再开新功能；启动任何一项前先确认前置条件与产品约束。

### 8.1 总览

| 事项 | 分类 | 状态 | 前置条件 | 对现有功能的影响 |
|---|---|---|---|---|
| 双端云同步 | 新子系统 | 暂缓（本轮不做） | 账号体系 / 云端存储 / 同步协议 | 无；替代方案为 JSON 备份导入 |
| 腾讯 COS 镜像 | 发布工程 | 待配置 | COS 桶 + 4 个 Secrets + 填入镜像地址 | 无；GitHub 单源更新正常 |
| 小程序嵌套仓库 | 工程结构 | 待用户决策 | 选择保留或删除内层 `.git` | 无；影响版本管理与交接 |
| 周期收支 | 新功能 | 未开工 | 无硬前置 | 无 |
| 月度账单提醒 | 新功能 | 未开工（依赖周期收支 / 月报） | 月粒度调度 + 常驻能力 | 无 |

### 8.2 双端云同步（暂缓）

- **目标**：桌面端 SQLite 与小程序本地存储互通，多设备看到同一份账本。
- **为什么暂缓**：这不是接线问题，需要新增账号 / 设备标识、云端存储（微信云开发按量计费，或自建服务）、同步协议、冲突合并、删除墓碑、断网重试与鉴权；会打破当前「本地优先、零网络请求、不接账号体系」的产品硬约束。
- **前置条件**：选定云端方案与费用模型；确定冲突策略（时间戳优先还是设备优先）；补齐隐私与合规文案。
- **现有替代**：设置页 JSON 备份 / 导入，可人工在两端迁移数据。
- **边界**：本轮未删除任何代码、未修改产品约束，仅登记为暂缓。

### 8.3 腾讯 COS 镜像（待配置，非砍掉）

- **用途**：作为 GitHub Releases 的备用下载源，缓解国内下载慢或失败。发布时把 `latest.json`、安装包与 `.sig` 同步到 COS，并把 `latest.json` 中的 `url` 改写为 COS 地址。
- **现状**：
  - `main.rs` 中 `MIRROR_ENDPOINT = None`，设置页选「国内镜像」会提示镜像源未配置；
  - `.github/workflows/release.yml` 已有可选同步步骤，4 个 Secrets 任一缺失即自动跳过；
  - Secrets：`COS_SECRET_ID`、`COS_SECRET_KEY`、`COS_BUCKET`（含 APPID）、`COS_REGION`（如 `ap-guangzhou`）。
- **前置条件**：创建 COS 桶；在 GitHub 配置 4 个 Secrets；把 `MIRROR_ENDPOINT` 填成 COS 上的 `latest.json` 地址并重新发版。
- **注意**：不配置不影响 GitHub 单源自动更新，因此优先级低于功能开发。

### 8.4 小程序嵌套仓库（待决策）

- **现状**：`简记小程序/` 内存在独立 `.git`，即「仓库套仓库」。外层主仓库只把它当 gitlink，不跟踪内部文件内容；本次核查内层有 16 条未提交变更。
- **影响**：小程序改动必须在子仓库单独提交；主仓库 clone 后可能拿到空目录或旧内容，交接与 CI 都存在隐患。
- **可选方案**：

| 方案 | 操作 | 结果 |
|---|---|---|
| A 保留内层仓库 | 进入子仓库单独 commit / push 到指定远端 | 双仓维护，主仓库仍看不到小程序改动 |
| B 移除内层仓库 | 备份后删除 `简记小程序/.git`，由主仓库统一跟踪 | 结构最干净；删除不可逆 |

- **建议**：优先 B。执行前先确认主仓库远端已包含小程序全部文件，并用一次全新 clone 验证；删除前务必备份 `.git`。
- **边界**：需用户明确同意后才能执行，本轮不做任何 git 操作。

### 8.5 周期收支（P2，未开工）

- **目标**：房租、工资、订阅等按周期自动生成记录。
- **已有基础**：`recurring` 表已建、`last_notified_month` 字段预留，但零命令、零 UI。
- **待实现**：
  1. `recurring` 的 Rust 模型与 CRUD 命令；
  2. 周期规则 UI（金额、分类、收支方向、频率、起止日期、备注）；
  3. 到点生成记录并按 `last_notified_month` 去重；
  4. 月末规则（29/30/31 号在小月如何处理）与漏生成补记；
  5. 修改 / 删除规则时，已生成记录的处理策略。
- **为什么暂缓**：属于完整新模块，不属于缺陷修复；涉及数据模型与交互决策，需单独评审。

### 8.6 月度账单提醒（P2，未开工）

- **目标**：每月固定日期推送上月收支汇总。
- **依赖**：周期收支或独立的月报汇总能力；Rust 定时器需从「日粒度 HH:MM」扩展到「月粒度」。
- **现状限制**：桌面端通知仅在应用运行时生效，尚未做开机自启 / 托盘常驻；即使实现调度，用户不开应用也收不到。
- **建议顺序**：先完成 8.5 周期收支与月报汇总，再评估是否需要常驻能力，最后接入月度提醒。

### 8.7 建议启动顺序

1. 小程序嵌套仓库决策（成本最低，先清理工程结构）；
2. 腾讯 COS 镜像（有密钥即可配置，纯发布工程）；
3. 周期收支；
4. 月度账单提醒（依赖第 3 项）；
5. 双端云同步（改动最大，需产品与费用决策）。
